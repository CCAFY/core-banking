# ADR 0001: 언어와 도구

- 날짜: 2026-11-26
- 상태: 확정

## 문제

은행 원장을 금융권 방식에 가깝게 만들어 보는 것이 목표다.
팀은 Java/Spring 경험은 있지만 C와 이 도메인은 처음이다.
금융권 도구를 전부 쓰면 도구를 익히는 데 시간을 다 쓸 위험이 있다.

## 검토한 대안

1. **금융권 구성 그대로**: C + Pro\*C + Oracle + TP 모니터(Tmax, Tuxedo).
   실제와 가장 비슷하지만 유료 제품이 섞여 있고 익힐 것이 많다.
2. **무료 대체품으로 같은 구조**: C + ECPG + PostgreSQL + Enduro/X(오픈소스 TP 모니터).
   구조는 비슷하지만 미들웨어 학습 부담이 그대로 남는다.
3. **원장만 남기기**: C + ECPG + PostgreSQL. 미들웨어 없이 함수 라이브러리로 만든다.
4. **C++로 원장만**: 자동 롤백 등 편의는 있지만 실제 계정계 언어와 거리가 생긴다.

## 결정

3번.

| 역할 | 결정 |
|---|---|
| 업무 로직 언어 | C11 |
| DB 접근 | ECPG (PostgreSQL의 임베디드 SQL 전처리기) |
| DB | PostgreSQL 16 |
| 빌드 | CMake |
| 테스트 | GoogleTest. 테스트 코드만 C++17, 검증 대상은 C 라이브러리 |
| 개발 환경 | Docker Compose (DB + 빌드용 컨테이너) |
| CI | GitHub Actions |

## 이유

- **C + 임베디드 SQL**: 국내 은행의 유닉스 계열 계정계는 C와 Pro\*C 조합이 흔하다.
  ECPG는 Pro\*C와 같은 임베디드 SQL 계열이라 코드 모양이 비슷하다.
- **PostgreSQL**: 원장 학습의 핵심인 트랜잭션, 잠금, 격리 수준을 제대로 연습할 수 있고,
  오픈소스라 로컬과 CI에 그대로 올릴 수 있다.
- **미들웨어 제외**: 원장 규칙(복식부기, 동시성, 멱등성, 대사)을 정확히 구현하는 데 시간을 쓰기 위해서다.
- **테스트만 C++**: GoogleTest를 쓰기 위해서다. 원장 코드에는 C++을 쓰지 않는다.

## 남은 한계

- TP 모니터, 전문 통신 같은 계정계의 운영 구조는 이 단계에서 다루지 않는다.
  지금은 원장을 함수 라이브러리로 만들고 테스트와 명령줄 도구에서 직접 호출한다.
- 원장 거래가 끝나고 시간이 남으면 아래 순서로 검토한다.

| 나중에 검토할 것 | 금융권에서 쓰는 것 | 무료 대안 |
|---|---|---|
| TP 모니터 | Tmax, Tuxedo | Enduro/X (AGPLv3, 무료 사용은 리눅스 한정) |
| 전문(고정길이 메시지) | TP 모니터의 구조체 버퍼 | 직접 구현 |
| Oracle + Pro\*C | Oracle Database | Oracle Database Free + Instant Client의 Pro\*C |

- C에는 예외도 자동 롤백도 없다. 오류 처리 패턴은 팀이 하나로 정해서 지킨다
  (docs/design-questions.md의 8번).

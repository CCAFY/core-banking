# 원장 불변식

어떤 거래를 몇 건, 어떤 순서로, 동시에 몇 개를 넣어도 항상 참이어야 하는 규칙.
이 문서는 요구사항이다. **어떻게 지킬지는 팀이 정하고**, 정한 뒤 오른쪽 두 칸을 채운다.

| # | 불변식 | 강제하는 곳 | 검증하는 테스트 |
|---|---|---|---|
| 1 | 금액은 원 단위 정수다. 소수 타입을 쓰지 않는다 | | |
| 2 | 금액 계산이 표현 범위를 넘으면 거래를 거절한다 | | |
| 3 | 모든 거래는 차변 합 = 대변 합이다 | | |
| 4 | 거래 기록은 추가만 가능하다. 정정은 취소(역분개) 거래로만 한다 | | |
| 5 | 같은 요청이 여러 번 와도 한 번만 반영된다 | | |
| 6 | 계좌 잔액은 거래 기록으로 다시 계산한 값과 항상 같다 | | |
| 7 | 동시에 들어온 거래에서 갱신이 유실되지 않는다 | | |
| 8 | 거래일자는 시스템 시각이 아니라 영업일을 기준으로 한다 | | |
| 9 | 잔액은 음수가 될 수 없다 | | |
| 10 | 실패한 거래는 흔적을 남기지 않는다 (전부 반영되거나 전혀 반영되지 않는다) | | |

## 칸을 채우는 기준

- **강제하는 곳**: 그 규칙을 깨려는 시도를 실제로 막는 장치. DB 제약, 트리거, 잠금, C 함수 등.
  "코드에서 조심한다"는 강제가 아니다.
- **검증하는 테스트**: 그 장치를 빼면 실패하는 테스트.
  장치를 뺐는데도 통과하면 그 테스트는 규칙을 검증하고 있지 않은 것이다.
